How Planagonia works

This page is written for people using the app, not for an AI generating plans from scratch — for the precise language grammar an assistant would need, see the language specification in the repository instead.

Getting started

Every plan is written in a small language, and rendered live next to the code that defines it. There's no "compile" step and no separate preview mode — the code pane on the left and the drawing on the right are two views of the exact same thing, always.

The smallest possible plan is a single shape:

element room {
  shape: "rect"
  size: [4m, 3m]
  position: [0m, 0m]
}

Paste that into the code pane in the app and you'll see a 4×3 meter rectangle appear. Drag it around in the viewer — the position values in the code update as you move it. Edit the numbers in the code instead, and the rectangle moves to match.

Elements

An element is the one building block the whole language is made of — a room, a wall, a piece of furniture, or just a reference point. Every element has an id (the word right after element) and a block of properties.

Shape and size

ShapeNeedsLooks like
"rect"size: [w, h]a rectangle
"circle"radius: ra circle
"polygon"points: [[x,y], ...]a closed shape
"polyline"points: [[x,y], ...]an open line (walls)

Leave shape off entirely and the element is just an invisible reference point — useful for marking a corner other shapes can point to (see Connections below).

Position and units

Every element has a position: [x, y] in real-world units — meters by default, or write 90cm for centimeters. Position is always relative to whatever the element is nested inside, not the whole plan — more on that below.

Style

style: { fill: "#cfe0f5", stroke: "#4a76a8", strokeWidth: 0.02 }

Plain color/stroke properties, same idea as CSS. strokeWidth is in meters too, like everything else geometric.

Labels

label: "Bett" plus show: "hover" or show: "always" puts a text label on the shape — hidden until you hover over it, or always visible.

Nesting means containment

An element written inside another element's braces becomes its child — and its own position is then relative to that parent, not the whole plan:

element room {
  shape: "rect"
  size: [5m, 4m]

  // bed sits 0.3m, 0.4m from the room's own corner — not the plan's
  element bed {
    shape: "rect"
    size: [1.6m, 2m]
    position: [0.3m, 0.4m]
  }
}

Add childPlacement: "inside" to a parent and its rect children are automatically kept from being dragged outside its own boundary — they slide along the wall instead of leaving the room.

Shared corners

Walls that actually meet at a point should share that point exactly, rather than two separate coordinates that happen to match. Give a shape's points a sibling element's id instead of a literal [x, y] pair, and it always resolves to that element's own current position:

Three corner elements, referenced by two wall segments — drag any one corner and both connected walls follow it.

element corner_1 { position: [0m, 0m] }
element corner_2 { position: [3m, 0m] }

element wall_a {
  shape: "polyline"
  points: [corner_1, corner_2]
  style: { stroke: "#444", strokeWidth: 0.1 }
}

Working in the app

  • Drag any shape to move it, or drag one of its corners to reshape it.
  • Click a shape to select it — its span in the code pane highlights, and small connect/disconnect icons appear where it touches other elements.
  • Right-click a shape for a context menu (currently: Delete).
  • Scroll to zoom the viewer, drag empty space to pan, and use the Fit button to reset the view.
Collisions and overlaps Two shapes are allowed to overlap by default — a rug under a table, say. Set allowCollisions: true on an element (or in a plan-wide settings {} block) to have it slide along whatever it bumps into instead of overlapping it.

Settings & modules

A plan can start with a settings {} block for plan-wide defaults:

SettingDefaultWhat it does
allowCollisionstruewhether siblings may overlap
allowSelfIntersectingPolygonsfalsewhether a polygon may cross itself
edgeLengthsfalseshow each edge's length by default

module "name.js" loads extra rendering or interactivity from a file — three modules load into every plan automatically (labels/dimensions, drag-and-drop, and the code-highlighting you're using right now if you're in the app), so you'll rarely need to write this yourself.

Saving & the cloud

Every plan you touch is saved automatically in your browser — no account needed. Use Open…/Save as… to move a plan to and from a file on your computer.

Sign in with a WordPress account (top of the app) to also explicitly push the plan you're working on to the cloud, or pull one you saved earlier back in — useful for picking up the same plan on a different device. This is optional and separate from the automatic local save, which always happens regardless of whether you're signed in.

Studio Apartment

A small room with a bed, desk, side table, and a rug — shared-corner walls with a door, containment keeping the furniture inside the room, and a connection linking the stove to the counter beside it.

Show the code 
element room {
  shape: "rect"
  size: [5m, 4m]
  position: [0m, 0m]
  style: { fill: "#f7f5f0", stroke: "#333", strokeWidth: 0.04 }
  childPlacement: "inside"

  element corner_1 { position: [0m, 0m] }
  element corner_2 { position: [2.2m, 0m] }
  element corner_3 { position: [3.1m, 0m] }
  element corner_4 { position: [5m, 0m] }

  element wall_a {
    shape: "polyline"
    points: [corner_1, corner_2]
    style: { stroke: "#444", strokeWidth: 0.1 }
  }
  element door {
    shape: "polyline"
    points: [corner_2, corner_3]
    style: { stroke: "#8a6a42", strokeWidth: 0.1, strokeDash: "0.15,0.1" }
    label: "Tür"
    show: "hover"
  }
  element wall_b {
    shape: "polyline"
    points: [corner_3, corner_4]
    style: { stroke: "#444", strokeWidth: 0.1 }
  }

  element bed {
    shape: "rect"
    size: [1.6m, 2m]
    position: [0.3m, 0.4m]
    style: { fill: "#cfe0f5", stroke: "#4a76a8", strokeWidth: 0.02 }
    label: "Bett"
    show: "hover"
  }

  element side_table {
    shape: "circle"
    radius: 0.35m
    position: [2.5m, 3.3m]
    style: { fill: "#bfe3f5", stroke: "#3a7a9a", strokeWidth: 0.03 }
    label: "Tisch"
    show: "always"
    dimensions: true
  }

  element stove {
    shape: "rect"
    size: [0.6m, 0.6m]
    position: [4.1m, 2.6m]
    style: { fill: "#d9534f", stroke: "#8a2f2a", strokeWidth: 0.02 }
    label: "Herd"
    show: "hover"
  }

  element counter {
    shape: "rect"
    size: [0.5m, 1.2m]

    label: "Ablage"
    show: "hover"
  }

  element rug {
    shape: "polygon"
    points: [[1m, 2.6m], [1.9m, 2.5m], [2.1m, 3.4m], [1.5m, 3.9m], [0.7m, 3.5m]]

    label: "Teppich"

Utility Connection

A property boundary, a house, and a power line reaching from the street to a fixed attachment point on the house — the same primitives used for a room work just as well outside one.

Show the code 
element grundstueck {
  shape: "polygon"
  points: [[0m, 0m], [11m, 0m], [12m, 9m], [-1m, 9m]]
  style: { fill: "#dce8c8", stroke: "#7a9a5a", strokeWidth: 0.06 }
  label: "Grundstück"
  show: "hover"
  edgeLengths: true

  element haus {
    shape: "rect"
    size: [5.5m, 4m]
    position: [3m, 3m]
    style: { fill: "#e8d6b8", stroke: "#8a6a42", strokeWidth: 0.08 }
    label: "Haus"
    show: "always"
    dimensions: true
  }

  element haus_anschluss { position: [3m, 4.5m] }

  element stromanschluss {
    shape: "polyline"
    points: [[1.5m, 0.5m], [1.5m, 4.5m], haus_anschluss]
    style: { stroke: "#e0a800", strokeWidth: 0.05, strokeDash: "0.3,0.15" }
    label: "Stromanschluss"
    show: "hover"
  }
}
