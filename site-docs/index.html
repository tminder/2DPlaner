How Planagonia works

This page is written for people using the app, not for an AI generating plans from scratch — an assistant needs the precise language specification instead, which isn't covered here.

Getting started

Every plan is written in a small language, and rendered live next to the code that defines it. There's no "compile" step and no separate preview mode — the code pane on the left and the drawing on the right are two views of the exact same thing, always.

The smallest possible plan is a single shape:

element room {
  shape: "rect"
  size: [4m, 3m]
  position: [0m, 0m]
}

Paste that into the code pane in the app and you'll see a 4×3 meter rectangle appear. Drag it around in the viewer — the position values in the code update as you move it. Edit the numbers in the code instead, and the rectangle moves to match.

Elements

An element is the one building block the whole language is made of — a room, a wall, a piece of furniture, or just a reference point. Every element has an id (the word right after element) and a block of properties.

Shape and size

ShapeNeedsLooks like
"rect"size: [w, h]a rectangle
"circle"radius: ra circle
"polygon"points: [[x,y], ...]a closed shape
"polyline"points: [[x,y], ...]an open line (walls)

Leave shape off entirely and the element is just an invisible reference point — useful for marking a corner other shapes can point to (see Connections below).

Position and units

Every element has a position: [x, y] in real-world units — meters by default, or write 90cm for centimeters. Position is always relative to whatever the element is nested inside, not the whole plan — more on that below.

Style

style: { fill: "#cfe0f5", stroke: "#4a76a8", strokeWidth: 0.02 }

Plain color/stroke properties, same idea as CSS. strokeWidth is in meters too, like everything else geometric. Instead of an inline object, style can also be a plain name pointing at a preset declared once in a plan-wide settings {} block (see Settings & modules) — handy once the same colors are reused across many elements.

Labels

label: "Bett" plus show: "hover" or show: "always" puts a text label on the shape — hidden until you hover over it, or always visible.

Nesting means containment

An element written inside another element's braces becomes its child — and its own position is then relative to that parent, not the whole plan:

element room {
  shape: "rect"
  size: [5m, 4m]

  // bed sits 0.3m, 0.4m from the room's own corner — not the plan's
  element bed {
    shape: "rect"
    size: [1.6m, 2m]
    position: [0.3m, 0.4m]
  }
}

Add childPlacement: "inside" to a parent and its rect children are automatically kept from being dragged outside its own boundary — they slide along the wall instead of leaving the room. A single child can set the same thing itself with placement: "inside" (or "outside", for something attached to a container's outer edge), and flush: true pins it exactly to the boundary it's touching instead of just somewhere inside it. In the app, the right-click menu's Placement submenu sets all of this for you.

Hiding things

Any element can be hidden: true — it, and everything nested inside it, is left out of the drawing entirely rather than just covered up. The app's Layers panel is the easiest way to toggle this without editing the property by hand, and reorder which elements paint in front of which.

Connections

A connection links two elements so dragging one carries the other along with it — useful for a piece of furniture that should always stay flush against another:

connection stove counter

In the app, you don't need to type this by hand: hold Ctrl (or Cmd on a Mac) and drag from one element onto another, anywhere on the canvas, and a small menu offers to connect them or, for a bare point dropped onto a rectangle, attach it to that rectangle's outside edge. Right-click an existing connection's own element for a Disconnect option. Connection lines stay hidden by default — hovering either end shows one temporarily, or set settings { showConnections: true } to keep every connection visible permanently.

Shared corners

Walls that actually meet at a point should share that point exactly, rather than two separate coordinates that happen to match. Give a shape's points a sibling element's id instead of a literal [x, y] pair, and it always resolves to that element's own current position:

Three corner elements, referenced by two wall segments — drag any one corner and both connected walls follow it.

element corner_1 { position: [0m, 0m] }
element corner_2 { position: [3m, 0m] }

element wall_a {
  shape: "polyline"
  points: [corner_1, corner_2]
  style: { stroke: "#444", strokeWidth: 0.1 }
}

Working in the app

Selecting, moving, and resizing

  • Click a shape to select it — its span in the code pane highlights. If it's completely covered by something else, click again at the same spot to reach it; hovering shows a small label listing everything stacked there.
  • Drag a selected shape to move it, or one of its corner handles to resize it (rectangles and circles — a shape built from corner references resizes by dragging its own corners instead).
  • Arrow keys nudge the selection by a small step; hold Shift and the same keys resize it.

The right-click menu

Delete, Duplicate (copies the whole shape, including anything nested inside it), Bring to Front/Send to Back, a Placement submenu (inside its container, flush to the edge, or free of both), and — once connected to something — Disconnect.

The rest of the toolbar

  • New Element (Edit tab) drops a fresh line, rectangle, circle, or polygon into the selected element, or the plan's own root if nothing's selected.
  • Undo/Redo (or Ctrl+Z / Ctrl+Shift+Z) cover every drag, edit, and menu action.
  • Grid and Snap are independent, each with its own flyout and its own spacing — a fine visual grid with coarse snapping, or the reverse, are both one click away.
  • Units switches the scale bar and dimension labels between metric and feet/inches — display only, a plan's own code always stays metric.
  • Layers lists every element in front-to-back order; hide one or reorder it with the ▲/▼ buttons — a hidden element is saved as hidden: true in the plan itself, not just remembered by the app.
  • Export gets the current plan out as a plan file, a PNG, or an SVG.
  • Scroll (or pinch, on a touchscreen) to zoom, drag empty space to pan, and use Fit to reset the view. Drag the thin divider between the code and the drawing to resize either pane.
  • On a phone, the editor splits into Code/Viewer tabs, and holding a shape opens the same right-click menu a long press away.
Collisions and overlaps Two shapes are allowed to overlap by default — a rug under a table, say. Set allowCollisions: true on an element (or in a plan-wide settings {} block) to have it slide along whatever it bumps into instead of overlapping it.

Settings & modules

A plan can start with a settings {} block for plan-wide defaults:

SettingDefaultWhat it does
allowCollisionstruewhether siblings may overlap
allowSelfIntersectingPolygonsfalsewhether a polygon may cross itself
edgeLengthsfalseshow each edge's length by default
styles—named style presets, referenced by name from any element's own style
gridoffbackground grid — size, layer, and opacity, also settable from the header
snapoffsnap-to-grid distance while dragging or resizing, independent of the grid above
keyboardStep0.1how far the arrow keys move or resize the selected element
showConnectionsfalsekeep every connection's line permanently visible, not just on hover
settings {
  styles: {
    wall: { stroke: "#444", strokeWidth: 0.1 }
  }
}

element wall_a {
  shape: "polyline"
  points: [corner_1, corner_2]
  style: "wall"
}

module "name.js" loads extra rendering or interactivity from a file — nothing loads unless a plan's own text declares it, including the editor's own drag-and-drop, pan/zoom, code-highlighting, and Layers panel. Every plan you start from inside the app (New, or any example below) already declares those four for you, so you'll rarely need to write them yourself; turning on Grid or Labels/Dimensions from the header writes that module's own line automatically too, the first time you use it.

Custom (external) modules

A module doesn't have to be one of this app's own built-in ones — module also accepts a full URL, fetched and run alongside whatever else a plan declares:

module "https://example.com/campervan-kit.js"

A module loaded this way can add new rendering (a shape kind the core language doesn't have), new interactivity, or a reusable higher-level building block composed from ordinary elements and connections — a "wall with a door" that expands from a few parameters instead of being written out corner by corner, for example (see the Studio Apartment example below). Browse what other authors have published at planagonia.com/modules.

You'll be asked before it loads The first time a plan declares a module that isn't one of this app's own built-in ones, the app asks whether to trust the URL before fetching and running it — module code runs with full access to the page, the same as any script you'd choose to add yourself, so only accept one from somewhere you actually trust.

Writing your own module means working directly against the app's own JavaScript API — that's developer territory, not covered here.

Saving & the cloud

Every plan you touch is saved automatically in your browser — no account needed. The header's Open and New buttons each open a full picker with a live preview of every plan or example, so switching or starting one means seeing it first, not just a name in a list. Use Import… to bring in a plan file, and Export to get the current one back out — as a plan file, a PNG, or an SVG.

Sign in (top of the app, or on the Profile page) to also explicitly push the plan you're working on to the cloud, or pull one you saved earlier back in — useful for picking up the same plan on a different device. This is optional and separate from the automatic local save, which always happens regardless of whether you're signed in. Don't have an account yet? Create one directly on the Profile page — you'll get an email to confirm it before you can sign in.

Campervan Build

A camper's interior split into three layer groups — furniture, electrics, plumbing — with the water tank tucked directly under the bench seat, a real packaging trick small campervans actually use. A fold-out table sits angled off the bench (rotation), a cabinet stays pinned flush against the van's own wall, and hiding the "Einrichtung" layer in the app reveals the tank underneath, exactly where an installer would need to see it. Collision checking is turned on plan-wide (allowCollisions: false) — the fold-out table itself opts back out with its own allowCollisions: true, since it's meant to overlap the bench it folds against.
