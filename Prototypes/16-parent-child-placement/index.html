Prototype 16: parent-child placement (containment)

Tests D-032's "inside" placement mode. Revised after the first round of testing: instead of connection child parent { placement: "inside" } — restating the parent's own id on every child, when nesting already makes that unambiguous — a child's own placement property (defaulting from the parent's childPlacement, if set) constrains it to stay within its parent's boundary when dragged, sliding along the boundary it hits rather than freezing outright. "sofa" here has no placement of its own and inherits "inside" from room's childPlacement; "lamp" overrides it back to "free" and can be dragged anywhere. Drag "sofa" around — it should never leave the room rect, and should slide along a wall if you keep pushing past it; drag "lamp" to confirm it isn't constrained at all.

Scope of this test: containment only, no flush combinable addition (D-032's door-in-wall half) — that's a separate, not-yet-built piece. Only a rect child with a plain literal position is supported; a rect parent gets an exact, non-iterative clamp, a polygon parent falls back to the general (still not fully validated) slide approach. No corner-refs, no connections, no self-intersection checking. A standalone local test, not wired into docs/.
