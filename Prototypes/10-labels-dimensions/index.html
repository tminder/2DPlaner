2DPlaner prototype: labels and dimensions

Two new, plain properties on any node — no new primitive, matching D-013's "just properties" philosophy. label: "text" shows a name. showDimensions: true shows the shape's own computed size (width × height for a rect, diameter for a circle) — not something the author types in by hand, so it can't drift out of sync with the actual geometry. show: "always" or "hover" — set per element — controls whether that node's annotation is always visible or only appears while hovering that specific shape. label was already part of D-013's Node definition ("an optional user-defined label/name") but no prototype had ever actually rendered it until now.

In this example: Brunnen (the fountain) and Schuppen (the shed) are always-on with dimensions; Beet (the garden bed) and Weg (the path) only show their label on hover, no dimensions. Try hovering each to see the difference, and try dragging the fountain or shed — the dimension text updates live since it's computed from the shape's actual size, not stored separately.

Scope, deliberately: showDimensions only has a computed value for rect (width × height) and circle (diameter) — shapes with a simple, unambiguous "size". For polygon/line, only label is supported; per-edge lengths or perimeter would be a reasonable extension but aren't built here. The hover-reveal relies on the annotation being the shape's next DOM sibling with nothing between them — true here because that's exactly how they're pushed into the render output, but it's a real constraint on the renderer's internal ordering, not something enforced structurally.

A real gap, not a corner case: nodes with no shape at all (the invisible corner/anchor nodes, e.g. bed_1–bed_5) can't carry a label in this prototype — renderAnnotation is only ever called from the rect/line/polygon/circle branches, not the D-016 anchor-hit fallback. "Every element individually" isn't fully true yet; labeling a bare point would need deciding what it should look like when the point itself has no visible shape to attach the text to.
