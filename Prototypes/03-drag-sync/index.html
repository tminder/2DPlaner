2DPlaner prototype: drag the plan → code updates (and back)

Throwaway prototype for core aim #1 ("code and plan change together") and D-009 (every visual element must be drag-and-drop editable). Builds on 02-text-parser: same syntax and renderer, plus dragging. Drag bed or window_center to rewrite a plain literal in the source. Drag desk to see D-012's solve-backward: its x position is the expression parent.size.x - 1.2m - 0.2m, so dragging it rewrites room's own size instead of the expression. Drag any wall segment to see D-014's rigid connection propagation: wall_a, door and wall_b are connected, so they move together. Hold Shift while dragging a connected node to move it alone, ignoring its connections — a UI escape hatch on top of D-014's default, not a change to the decision.

Known simplifications, honestly: connection propagation here is a uniform translation of everything reachable in the connection graph (the "simple chain" case F-001 asked for first) — no per-endpoint constraint solving, no rotation, and D-014's symmetric-vs-directional distinction isn't honored (everything propagates both ways). Solve-backward (D-012) only handles one level of parent.<prop>.<x|y> in a linear +/-/*// chain. An unsolvable drag is rejected with a message rather than D-015's "complete visually and flag" — implementing a true visual-only override wasn't worth it for this throwaway.
