2DPlaner prototype: performance at scale

Tests F-007 directly instead of just reasoning about it: 03–10 all re-tokenize/re-parse the *entire* plan text and replace the *entire* rendered SVG via innerHTML on every single pointermove, not just at drag-end. This generates a plan with N simple objects, using the same tokenizer/parser/renderer as the other prototypes (unchanged — this is about measuring the existing architecture, not a different one), and times how long one full parse+render cycle actually takes at each size, plus lets you actually drag an object in each size to feel it, not just read a number.

No devtools/profiler needed to read this — everything is measured with performance.now() and printed on the page. One caveat: this measures parse+render cost, not full pointer-event-to-paint latency (actual dragged-object responsiveness also depends on the browser's own paint/composite step, which this doesn't isolate) — treat the numbers as a lower bound on per-drag-step cost, and the actual drag feel as the more honest signal.
