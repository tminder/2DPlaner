2DPlaner prototype: connections, concretized — a kitchen row

Throwaway prototype to concretize D-014 (Connection semantics) for the case it was never actually tested on: two solid, adjacent objects — herd (stove) and ablage (counter) — connected via connection herd ablage, not two lines sharing an endpoint (that's D-018, already well covered by 04/05). Deliberately minimal: no expressions, no points-as-references, no settings — just rectangles, one connection, and dragging.

Try it: drag herd normally — ablage moves with it, rigidly, per D-014's decided mechanic (uniform translation). Now hold Shift and drag herd alone — the connection is ignored, and the two drift apart. Ask yourself: for a kitchen row, is "always rigidly together" actually what you want, or did you expect something looser — e.g. "stay flush against each other" while still being able to slide one along the counter run independently?

This is exactly the question D-014's status note raises: the mechanic was designed around a case (shared wall/door endpoints) that D-018 later solved differently. Here it's applied to its actual remaining case for the first time. Whatever this feels like is real evidence for deciding whether to carry Connections forward as-is, change the mechanic, or drop them.
