2DPlaner prototype: unified

Terminology note: this prototype predates D-033's rename of the node keyword to element and allowUnrealisticPolygons to allowSelfIntersectingPolygons — kept as originally built, not rewritten. See 15 for the current names.

Everything validated in 01–12, combined into one plan: a small studio apartment. Walls with a door share exact corner points (D-018); bed/desk/side_table are plain rects/circle; rug is a 5-point polygon (also via shared corners); stove and counter are joined with a real connection (drag one, both move — try it, then select either and use the × icon at their contact point to disconnect). Drag them apart and back near each other, then hit the + icon to reconnect — it snaps them exactly flush even if the drag left a small gap or overlap, rather than connecting them wherever they happened to land. desk's label/show/dimensions demonstrate D-026, and star_decoration is rendered entirely by the "star-tool" module declared in the preamble — the core renderer has no built-in idea what a "star" is.

An earlier version of this example gave desk an expression-backed position (parent.size.x - 1.2m - 0.2m) specifically to demonstrate D-012 solve-backward. In practice, that meant dragging the desk resized the entire room — reported back as nonsensical, correctly: a piece of furniture moving shouldn't move the wall. Solve-backward itself still works (see D-012 in decisions.md for where it's actually appropriate); this particular composition, rewriting a parent's own size as a side effect of moving a child, just isn't a good default and was removed from the example rather than kept as a "this is fine" demo. desk's position is a plain literal now.

Deliberately not attempted here: no live constraint solver beyond D-012's simple linear solve-backward (F-001), connections only work between rect-shaped nodes since adjacency is computed from axis-aligned bounding boxes (matches 08's scope note), and modules only get to contribute a shape renderer — no interactivity hooks, no "selected" outline on star_decoration (F-002 remains rendering-only). No backend: this is still frontend-only, per the explicit scope for this prototype.

One real bug found while building this and fixed here (not present in the individual 09/10 prototypes only because their examples never happened to hit it): the parser's "is this a plain editable literal" check only recognized a bare number token (5m), not a unary-negated one (-5m) — so a node dragged to a negative coordinate would parse back as a plain non-editable number and silently stop being draggable on the next move. Fixed by also recognizing neg(num) as an editable literal, spanning from the minus sign through the number.

Two more bugs found from actually using this, both fixed: selecting room (a rect that's also the parent of every piece of furniture) offered a connect-icon to nearly everything inside it, since 08's adjacency test only checked "do these boxes overlap" — true for full containment, not just edge contact. Fixed by requiring a genuine near-zero gap on one axis, not just any overlap. Separately, dragging one object across a polygon's corner lit up that corner as if hovering it directly — without setPointerCapture (dropped early on, see D-009), the pointer still fires over/out events for whatever's actually under the cursor mid-drag. Fixed by suppressing the hover preview while a drag is active.

A naming/syntax review then changed six things (see D-029 in decisions.md): the open line shape is now "polyline" (was "line" — misleadingly implied exactly 2 points); showDimensions is now dimensions (no longer sharing the word "show" with the unrelated show visibility property); style.dash is now style.strokeDash (consistent with strokeWidth — both are stroke-only); and connection now accepts an optional trailing { ... } for properties (e.g. kind, D-014), which had no syntax at all before. One caveat on that last one: removeConnection deletes a connection by its whole *line*, so a property block written across multiple lines would only be partially removed — fine for what this prototype ever writes itself (always one line), a real gap if hand-formatted differently.

Right-click any object for a custom context menu (D-030), replacing the browser's default one — currently just Delete Element, more to follow. Deleting removes the node's own block plus any connection mentioning it; deleting the plan's root or a node still referenced as a shared corner (D-018) is refused with a message instead of silently breaking whatever depends on it.
