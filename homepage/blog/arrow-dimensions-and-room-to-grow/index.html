Product update

Arrow Dimensions, Cleaner Plans, and Room for Modules to Grow

October 6, 2026

Three updates that each make a plan a little easier to read, a little less cluttered to write, or a little easier to build on — a real dimension-line style for measurements, a way to drop the unit suffix from every single number in your plan, and the first real way for someone else's code to add its own button to the app you're already using.

Dimension lines that actually look like dimension lines

Edge lengths have always been able to show themselves as plain text next to a shape — a small "4m" floating by a wall. That's fine for a quick glance, but it doesn't read the way an actual drawing does. There's now a second style: a proper dimension line, with witness ticks at each end and an arrow-tipped line running between them, the measurement sitting right on top. Switch a whole plan over to it with one click of the header's Dimensions button, or write it directly as settings.dimensionStyle: "arrows".

It's deliberately just the line style — the editor doesn't yet try to notice that three walls happen to line up and offer to sum them into one long dimension chain with a running total the way a CAD tool might. That's a genuinely bigger feature on its own, and it's still on the list. For now it's one style switch, applied everywhere edgeLengths is already turned on. The Studio Apartment example in the app now ships with it on, if you want to see it against a real plan before trying it on your own.

A plan that doesn't repeat its own units on every line

Every number in a plan has always needed its own unit written right on it — size: [5m, 4m], position: [0m, 0m], and so on for every single value in the file. It was never actually necessary: a bare number already meant meters, the suffix was only ever there for clarity. Now a plan can say that once, up front, instead of on every line:

  • settings { units: "m" } — the default, and the one every existing plan already behaves as.
  • settings { units: "none" } — new values the editor writes for you (a shape you drag, a new element you drop in, a grid size you set from the menu) come out bare, no suffix, and your own plans read cleaner too.

Worth being precise about what this isn't: it's not the feet-and-inches toggle from a few weeks ago — that one only changes how numbers are *displayed* to you, in the scale bar and dimension labels, and never touches your plan's own code at all. This is the opposite kind of thing: it changes what your plan's own code actually looks like, while the numbers themselves still always mean meters underneath, exactly as they always have. Two different knobs for two different jobs — what you see, and what you write.

Room for someone else's code to add its own button

Planagonia has always let a plan load a module — someone else's code that teaches the editor to draw something new, or react to clicks in a new way. Up to now, a module could only ever change what's happening *inside* the plan itself. It had no way to add anything to the app's own header around it. Now it can: a module can register its own single-click button, which shows up either in its own dedicated "Modules" tab or tucked into an existing one, wherever makes sense for what it does.

If you're not writing your own modules, this one's invisible to you — nothing changes about how the app looks or works today. If you are, it's a real new door: a module's own feature no longer has to live entirely inside the plan's canvas to be reachable.

Want to try any of this? Open the app — everything above is already live, no update needed on your end.

Small on their own, but each one removes a little friction from somewhere different — reading a measurement, writing a plan, or building something on top of the app itself.
