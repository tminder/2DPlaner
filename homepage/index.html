Three ideas the whole language is built around

Not a general drawing tool with a scripting layer bolted on — the language and the renderer were designed together, for exactly this job.

01

Code and plan never drift apart

There's no view that can silently fall out of sync with the code defining it. Editing the drawing rewrites the source; editing the source redraws the plan — the same underlying model, always.

02

A language built for this, not for everything

Real-world units, positions that solve themselves when you drag something, shapes and connections as the only two building blocks. No general-purpose programming required to describe a room.

03

Extensible from inside the plan

New shapes, new interactions, new behaviors load as modules declared right in the plan's own source — the core language stays small on purpose.

Written to be authored by AI, reviewed by you

Planagonia's language favors precision an AI can generate unambiguously over convenience for hand-typing — describe what you want built, let the assistant write the plan, and check the result against the live drawing.

It's still plain, readable source either way — open the app and edit it directly whenever you'd rather.
