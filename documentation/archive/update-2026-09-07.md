# Update — 2026-09-07

Everything built since [update-2026-09-03.md](update-2026-09-03.md), across several working sessions on 2026-09-03 through 2026-09-05 and one long session on 2026-09-06/07. Where the last update was mostly about a deliberate design review and the bugs it surfaced, this one covers a lot more ground: several small, directly-requested language features shipped in quick succession, a real committed test suite arriving and immediately paying for itself, two rounds of tracked technical debt paid down, a from-scratch header/relationships redesign, the test suite going fully automatic via CI, four new editor features (a hierarchy panel, a plan picker, a resizable pane split, real touch support), a cluster of real production bugs in the auth backend found and fixed live, and — new this update — a standing decision about intellectual property and commercial viability. As before, this is a readable summary, not a replacement for [planning/decisions.md](../../planning/decisions.md) — every `D-xxx` reference points at that entry for the full reasoning.

- **A real, committed test suite arrived (S-030) and started paying for itself immediately** — Python + pytest + Playwright, chosen only after confirming Node wasn't actually available in this environment. Two more rounds of tracked technical debt were paid down against it (S-001, S-002/S-003/S-004).
- **The header was redesigned from scratch and relationships between elements were rebuilt end to end** — every action flat and always visible, a real sign-in popup, and creating a connection is now a Ctrl/Cmd-drag between any two elements regardless of distance, not just touching ones.

- **Four substantial editor features**: a collapsible hierarchy/layers panel with show/hide and reordering; a full-width plan picker with live previews, replacing the old dropdown; a resizable code/viewer pane split; and real touch support (pinch-to-zoom, a long-press context menu, and visible drag handles for resizing a shape directly).
- **A real production bug report turned into a four-fix chain on the live WordPress/MySQL auth backend** — a broken verification link, the actual root cause of "Invalid credentials" for any email address with a dot in it, sign-in now accepting an email address, and a full "forgot your password" flow built from scratch.

## Five small language/settings features, each its own short pass (D-081, D-082, D-084, D-085, D-092)

- **A version marker** (`settings { version: 1 }`) — pure forward-compatibility placeholder, nothing branches on it yet, but there was previously no way at all to tell which revision of the language an old saved plan assumed.
- **Named style presets** (`settings { styles: { wall: { stroke: "#444" } } }`) — any element's `style` can now be that same inline object, or a plain string naming a preset. Building this caught a real, second bug: a plan referencing an *unresolvable* preset name didn't just lose its color, it silently lost its shape too, falling all the way through to an invisible anchor-point render.
- **A full property schema** (F-023) — closing the last of D-075's own load-time validation gaps: an unrecognized `shape`, a property a given shape doesn't actually support, `dimensions` on a polygon or `edgeLengths` on a circle (both already documented as meaningless, neither previously enforced), and `flush: true` with no `placement` to make it mean anything, are now all flagged the moment a plan loads, not just discovered by accident.
- **A checkered (or line) background grid** (`settings { grid: { size: 1, type: "checker" } }`) — a new, auto-loaded, pure-display module, deliberately driven entirely by the plan's own settings rather than a separate viewer toggle.
- **A real Placement submenu** in the right-click menu — "Inside `<parent>`," "Snapped to `<container>`'s edge," "No placement," always shown with a checkmark on whichever is active, choosing one immediately snaps the element into a valid position instead of leaving it wherever it was.

## A real, committed test suite (D-093), and two rounds of technical debt paid down against it (D-095, D-096)

**Python + pytest + Playwright** — the exact toolchain every ad hoc manual check already used successfully — chosen only after directly confirming Node/npm weren't actually available in this environment, not assumed. A curated initial suite (not a wholesale port of dozens of one-off scratchpad scripts): shipped examples, drag/undo, containment/placement/flush, the validation pass, the stacked-elements subsystem, and the context menu's structural actions. Writing it surfaced two real bugs — both in the test *helpers*, not the product, each traced to its actual mechanism rather than assumed.

With a real regression suite now in place to check against, two tracked tech-debt clusters were tackled directly:
- **S-001**: read all six of the interactivity module's "clamp/slide" functions in full before touching anything — found they're four genuinely *different* algorithms wearing a similar name, not four reinventions of one problem (forcing them into one function would have been the premature abstraction this project's own principles warn against, not a cleanup). What actually was duplicated, byte-for-byte, five times across three functions, got extracted into one small helper; the rest was deliberately left alone, a checked finding rather than a skipped task.
- **S-002/S-003/S-004**: six near-identical menu-action functions' shared parse-guard-edit-apply-commit shape, and three coexisting "apply an edit to text" idioms, both genuinely collapsed this time — unlike S-001, there was no hidden "these are actually different" trap here. A small, previously-silently-dropped function argument (S-004) was fixed along the way, in the same call site this refactor already touched.

## The header redesigned, relationships rebuilt end to end (D-100, D-101, D-103, D-107)

After several rounds of direct feedback, the header settled on one shape: every genuinely distinct action sits flat and always visible in the header, icon-led, no dropdown for the sake of tidiness — Export is the one deliberate exception, grouping its three file formats as one action's own variants, not hiding otherwise-separate actions from each other. Sign-in and registration became a real popup instead of native browser dialogs. (This redesign — plus the automated test suite and a showcase example built from the new style presets — is also told in plain language in [the blog post about it](https://www.planagonia.com/blog/the-toolbar-we-redesigned-three-times/).)

**Creating a relationship between two elements no longer requires them to already be touching.** The old contact-point-only +/- icons are gone, replaced by a Ctrl/Cmd-drag gesture that works between any two elements regardless of distance, ending in a small choice menu — "Connect to X," or, for a bare point dragged onto a rect, "Attach outside X" (finally giving that placement mode a real starting position to snap to, a gap that had been open since much earlier in the project). Removing a connection moved into the right-click menu. Visibility is a new opt-in setting, plus two always-on hover aids added directly from feedback after shipping: hovering any node in a connected chain shows the *whole* chain, and the Ctrl-drag gesture itself shows a live line tracking the cursor. Building this found and fixed two real, previously-unreported bugs, including one where a fundamental coordinate-conversion helper had been silently wrong by whatever amount the viewer's own letterboxing offset happened to be — affecting both this new drag-line and the existing zoom-to-cursor behavior.

## The test suite goes fully automatic (D-108)

**GitHub Actions now runs the whole suite on every push and pull request** — deliberately test-only, not deploy: the actual `scp` deploy step was left manual on purpose, since automating it would mean putting a real SSH key into GitHub's secrets, a security-posture change not made unilaterally. This closed the exact gap that had let two real bugs reach production before being caught live rather than automatically.

## Four editor features (D-109 through D-116)

- **Keyboard-driven move and resize.** Arrow keys nudge the selected element; Shift+arrow resizes it; both use a configurable step size, deliberately kept independent of the background grid's own size.
- **A resizable code/viewer split** — a draggable divider between the code pane and the plan viewer, remembered per browser, keyboard-resizable, hidden on mobile.
- **A third editor panel: hierarchy/layers.** Shows the full parent/child tree, lets a layer be shown or hidden via a real `hidden: true` property (a hidden subtree is genuinely absent from rendering *and* every interaction, not just visually dimmed), and reorders siblings. A new "Campervan Build" example was built specifically to show this off — a bench seat that can be hidden to reveal the water tank underneath it.
- **A real plan picker.** The old cramped dropdown for switching or starting a plan was replaced with a full-width panel, opened separately for "Open" and "New," showing every plan (or example) as a live-rendered preview instead of a bare name.
- **Real touch support**: genuine two-finger pinch-to-zoom, a long-press equivalent for the right-click context menu, and — closing a long-standing open question about how "Scale" would ever work — visible, draggable resize handles on the selected shape's own corners (or, for a circle, its radius), usable on both mouse and touch since both ride the same underlying gesture system.

## A tech-debt cluster, and a real production bug chain in the auth backend (D-114, D-117 through D-120)

**A small tech-debt cluster** closed three tracked items in one pass, including a real (if narrow) bug: a module referenced by a path-qualified name kept popping an "untrusted code" confirmation dialog every session even though it was one of this app's own shipped, trusted modules.

**A real bug report — "the verification email link doesn't work" — turned into a chain of four related fixes, each found by testing against the actual live WordPress/MySQL backend, not assumed from reading the code:**
1. The emailed link pointed at the main site's own domain instead of the API's — a flat "File not found."
2. **The deeper cause of "Invalid credentials," affecting far more than one broken link:** WordPress's own API returns two different fields for a user — the real login name, and a separate, URL-safe version that turns dots into hyphens — and this project had been using the wrong one everywhere. Since most real email addresses contain a dot, this had been silently breaking sign-in for a large fraction of possible accounts, not a rare edge case.
3. Signing in now explicitly works with an email address, not just a username — it already did on the backend; only the form's own label was misleading.
4. **A full "forgot your password" flow, built from the ground up** — reusing the existing registration/verification machinery unchanged, since it already did the right thing regardless of an account's prior state. Covers both "I lost my one-time password" and "my account predates self-registration and never had one issued at all."

## A standing decision on commercial viability and IP (D-121)

**A new project goal, added directly: the project should eventually be commercially successful, with intellectual property protected accordingly.** The key fact that shaped the first concrete answer: this app's own client-side code ships fully readable to any visitor via "View Source," completely independent of whether the source repository itself is public or private — so client-code secrecy was never really on the table. Decided: the *hosted service* (accounts, cloud sync, and whatever comes after) is the actual protectable value, not the code. The repository stays public; a `LICENSE` file now makes the previously-implicit "all rights reserved" explicit rather than silent.

## Grid-snapped dragging, and inline validation markers (D-122, D-123)

**Declaring a background grid now also constrains where a drag or resize can land** — every element snaps to an exact multiple of the grid's own size, both for ordinary dragging and for the resize handles, hard snap with no exception, deliberately tied to the one existing grid setting rather than a second flag so the two can never show a different value from each other.

**A validation error now marks the exact offending spot directly in the code**, not only in the separate panel — a wavy underline under the specific property or element name, the panel itself unchanged alongside it. The parser change needed for this turned out much smaller than originally expected once every actual violation type was reread carefully — none of them needed a value's own position, just a property name's, which was already available and simply being discarded. Two real dead ends were hit and abandoned while building the hover-tooltip half of this — a native tooltip fundamentally can't fire on this pane's own layered structure, and neither can the more sophisticated custom replacement that was tried next — decided directly to do without a tooltip on the mark itself rather than build something substantially more complex than the feature warranted.

- **The test suite has grown from 44 tests (last update) to 110**, and now runs automatically on every push, not only when a session remembers to invoke it by hand.
- **`planning/core-aims.md` grew from four standing goals to six** — commercial viability/IP protection, and keeping the core as lean as possible in favor of building new capability as a module.
- **`planning/open-questions.md` and `planning/tech-debt.md` remain the current, living account of what's left** — several long-standing open questions (grid-snapping, the resize-handle mechanism, inline validation) closed this update, while a few new ones were recorded alongside the IP decision (a community module store, and the still-open pieces of commercial viability beyond where the protection comes from).
